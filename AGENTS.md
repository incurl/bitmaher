# AGENTS.md

Repository instructions for AI coding agents. Keep this file short, concrete, and tied to commands that actually work in this
repo. If a fact here conflicts with source files or CI config, trust the source file and update this guide.

## Project Snapshot

BitMaher is a **desktop download manager** for Linux, macOS and Windows. A Vue 3 interface drives the
[Aria2-Next](https://github.com/AnInsomniacy/aria2-next) engine, and PocketBase is the database.

The interface is a **port of Rayburst**, the frontend of
[Motrix Next](https://github.com/Rayburst/Motrix-Next), which is MIT licensed. The attribution is in
`THIRD_PARTY_NOTICES.md`.

- Backend: Go 1.26 (toolchain pinned in `go.mod`), Wails v3.0.0, PocketBase v0.39.11. The binary is `main.go` at the repo root.
- Frontend: Vue 3, TypeScript, Vite, Pinia, vue-i18n and Naive UI, ported from Rayburst. The package manager is
  **pnpm** (`/home/peter/.local/bin/pnpm`, which needs the Node of `/home/peter/.local/bin`).
- The download engine: **Aria2-Next, a separate GPLv2 child process, driven over JSON-RPC.**
- Persistence: PocketBase owns the database (SQLite). It runs **as a library**, never as a process. Collections are defined in
  `internal/pocketbase/migrations/*.go` and registered through a blank import in `internal/pocketbase/service.go`.
- Generated API outputs: `frontend/bindings/` for TypeScript. It is generated by `wails3 generate bindings` and is **gitignored**.
  Never hand-edit it, never commit it.
- Module path: `github.com/incurl/bitmaher`.

## The One Rule That Matters Most

**Aria2-Next is a separate process, and it must stay one.**

The engine is GPLv2. BitMaher is MIT. The two stay apart because:

- the engine is started as its own process, with its own address space;
- the only channel is a loopback HTTP socket carrying JSON-RPC;
- nothing links against it, imports its headers, vendors its sources, or reaches it through CGO;
- the binary is shipped as an opaque executable, and the bundled binaries are **not** in Git.

Breaking that boundary changes the licensing of the whole application. `internal/aria2/manager.go` and `main.go` carry the note;
`THIRD_PARTY_NOTICES.md` explains it to a reader.

## Architecture

```
Wails webview
├── Vue 3 + Vite + Pinia + vue-i18n + Naive UI
│   ├── api/           the calls to the backend, and the adapters of its shapes
│   ├── components/    one panel per concern (task, layout, preference)
│   ├── composables/   the reusable behaviour (platform, reduced motion, scaling)
│   ├── platform/      the Tauri-compatible layer over the Wails runtime
│   ├── stores/        the Pinia stores (task, app, engine, preference)
│   ├── shared/        the pure logic: the types, the constants, the helpers
│   └── styles/        the design tokens
│
└──── Wails bindings (the only channel) ───────────────────────┐
        Go: internal/bindings/ → internal/downloads/ → internal/aria2/
                                    │                    │
                                    └→ internal/pocketbase/    └→ aria2-next (child process)
                                        (embedded, library)        JSON-RPC on 127.0.0.1
```

`internal/aria2` owns the process: the port, the secret, the watchdog, the log capture, the typed client. `internal/downloads`
owns the domain: the records, the status mapping, the service the bindings call. The engine's vocabulary never leaves
`internal/aria2`.

## Working Rules

- Read relevant code before editing; prefer local patterns over new abstractions.
- Keep diffs scoped. Do not do repo-wide cleanup, dependency churn, or generated-file rewrites unless the task requires it.
- **The frontend never talks to PocketBase or to the engine directly.** Every call goes through `internal/bindings` and the
  typed wrappers in `frontend/src/bindings/index.ts`. If a component needs new backend behaviour, add a method to `AppService`,
  regenerate the bindings, and add a wrapper.
- **Never hand-edit `frontend/bindings/`.** It is generated and gitignored. Change the Go service, then run
  `wails3 task common:generate:bindings`.
- **Never hand-edit `frontend/dist/`.** It is the `//go:embed` payload, built by Vite and gitignored.
- New collections and fields go in `internal/pocketbase/migrations/` as a Go migration registered in an `init()`. The file
  name is the migration's identity *and* its ordering key: the list is sorted by name, so a new migration must be named with a
  timestamp that sorts after the ones already applied (`1730000000_init.go` → `1732000000_bitmaher_downloads.go`).
- PocketBase's collection access rules are the write gate. `download_jobs`, `job_logs` and `bt_presets` are read public and
  write closed. `app_settings` has **no** rule at all, so only the Go backend can read it. Do not open `app_settings`.
- Secrets are write-only from the UI's point of view. The RPC secret and the API key are encrypted with AES-256-GCM before they
  are written, and the key lives in a `0600` file in the data directory. Never return a secret from a bound method.
- Ask before adding heavy dependencies, changing auth/token behaviour, or altering the Docker/release workflows.

## The Engine's Behaviour, As Verified

These were measured against aria2-next 2.8.2 and 3.0.9, not assumed. They shape the design; do not "fix" the code to match
what the upstream aria2 documentation says.

| Fact | Consequence |
| --- | --- |
| The engine pushes nothing, and there is no `aria2.onDownloadStart` | The interface polls `SyncDownloads`; there is nothing to subscribe to |
| Errors arrive as a JSON body on HTTP 400 in 2.8.2 and on HTTP 200 in 3.0.9 | The client parses the body whatever the status |
| The method is `aria2.getFiles`, not `aria2.tellFiles` | See `rpcclient.go`; `tellFiles` does not exist |
| The method is `aria2.changeGlobalOption`, not `aria2.setGlobalOption` | Same |
| `tellWaiting` and `tellStopped` need an offset and a count | `tellActive` does not |
| `select-file` works only as an option, and only while paused | The backend pauses, changes, resumes |
| A magnet has no file list until its metadata has been fetched | File selection is offered once the files are known |
| `--input-file` fails when the session file does not exist | It is only passed once the file is there |
| The session file carries the gid | A download survives a restart, with the same gid |

## Commands

Run from the repository root unless a command starts with `cd`.

**`wails3` is not on the default PATH of non-interactive shells.** It lives in `~/go/bin`. The `task` binary is *not* needed
— `wails3 task` runs the Taskfiles itself.

```bash
# Backend
gofmt -l internal/ main.go main_test.go tools/   # must print nothing
go vet ./internal/... .
go test -race ./internal/... .

# The live checks, against a real engine
go run ./tools/e2e-check         # the whole pipeline, with a real sidecar
go run ./tools/pump-check        # the pump publishes the snapshots, with a real sidecar
go run ./tools/zoom-check        # the window carries the zoom of the interface
go run ./tools/commands-check    # the commands the port added, with a real sidecar
go run ./tools/restart-check     # a download survives a restart
go run ./tools/watchdog-check    # a crashed sidecar is started again
go run ./tools/bundled-check     # the embedded binary is found and run
go run ./tools/leak-check        # no sidecar outlives the application
go run ./tools/torrent-check     # a torrent's files are listed and chosen

# Frontend (from frontend/)
npm install --legacy-peer-deps   # npm 9 cannot resolve the vitest 4 tree
npm test                         # vitest
npm run typecheck                # tsc --noEmit, includes the test files
npm run build                    # tsc && vite build -> frontend/dist

# Bindings and builds
PATH="$HOME/go/bin:$PATH" wails3 task common:generate:bindings
PATH="$HOME/go/bin:$PATH" wails3 task common:fetch:aria2    # the bundled binaries
PATH="$HOME/go/bin:$PATH" wails3 task build               # -> bin/bitmaher
PATH="$HOME/go/bin:$PATH" wails3 task package             # the platform packages
PATH="$HOME/go/bin:$PATH" wails3 task --list-all          # every task, with names

# Audits
python3 tools/license-audit.py   # fails on a copyleft dependency
```

### Task names are namespaced

The Taskfiles are `include`d under `common:`, `linux:`, `windows:`, `darwin:`, `ios:` and `android:`. The bare names in the
root `Taskfile.yml` (`build`, `package`, `run`, `dev`) work, but the tasks defined in `build/Taskfile.yml` are only reachable
through their namespace: `common:generate:bindings`, `common:fetch:aria2`, `common:install:frontend:deps`.

**`wails3 task --summary <name>` executes the task; it does not describe it.** To list, use `wails3 task --list` or
`wails3 task --list-all`. To inspect without running, use `wails3 task --dry <name>`.

## The Commands of the Port

The ported frontend calls the Tauri commands of Rayburst by name. The
Go backend answers the ones that belong to a download manager, and the
rest answer with the neutral value, so that the components that call
them stay inert.

What the backend answers:

| Area | The commands |
| --- | --- |
| The files | `check_path_is_dir`, `delete_path`, `list_dir_files`, `rename_completed_file`, `read_local_file`, `write_local_file` |
| The categories | `resolve_file_category`, `validate_file_categories` |
| The preview | `preview_download`, `cancel_download_preview` |
| The state of the files | `task_file_states` |
| The engine | `engine_recover_runtime_state`, `engine_cancel`, `engine_supervisor_state` |
| The notifications | `send_app_system_notification`, `notification_access_state`, `open_notification_settings` |
| The BitTorrent blocklist | `get_bt_peer_blocklist_status`, `sync_bt_peer_blocklist`, `reconcile_bt_peer_blocklist` |
| The remote files | `fetch_remote_bytes`, `preview_site_rules` |
| The application | `set_app_log_level`, `export_diagnostic_logs`, `factory_reset`, `database_reset` |

The categories are the ones Rayburst uses, so that the two
applications classify a download the same way. The rules are in
`internal/downloads/category`, and the tests are the ones Rayburst
wrote for its own rules.

The preview asks the engine: `aria2.probe` is what the engine has
instead of a request of its own, and it answers with the size and the
name a download would get.

## The Platform Layer

The ported components are written against the **Tauri API**. `frontend/src/platform/` implements that API on top of the
Wails runtime, and the Vite aliases point `@tauri-apps/*` at it. Three rules follow:

- **The platform layer is the only place that knows about Wails.** A component calls `invoke()`, `listen()` or `getCurrentWindow()`,
  and the platform layer turns it into a Wails call.
- **`commands.ts` is the command map.** It maps Rayburst's Tauri commands onto the Go methods. A command with no counterpart
  maps onto a method that answers the neutral value, and the feature it belongs to stays inert.
- **`tasks.ts` is the shape adapter.** The backend normalises the engine's state into records with numbers; the ported
  components read the engine's own shape with strings. The adapter sits between them.

A component that needs a new backend operation gets a method on `AppService`, the bindings are regenerated, and the command
map gains an entry.

## The Header and the Size of the Interface

Two things belong to BitMaher rather than to the port, and they are the
first things to keep when the interface changes.

**The header** (`frontend/src/components/layout/AppHeader.vue`) is the
band across the top: the application's icon, its name, the speed of all
the downloads together, and the two controls that are not about the
downloads. It is a grid row of its own, so the layout below it shifts by
one row when it appears.

**The size of the interface** is the zoom of the webview. The frontend
holds it as a factor (`uiScale`), the backend stores it as a percentage
(`ui.Zoom`), and the store is where the two meet:

- the frontend applies it with `Window.SetZoom`, through the platform
  layer's `setZoom`;
- the backend applies it too, when the setting is written, so that the
  change shows at once while the user moves the slider;
- the backend reads it at start-up, so the interface appears at the size
  the user chose.

Every size in the stylesheet is in `rem`, so the zoom scales the whole
interface, text included.

## Frontend Conventions

- One panel per concern under `frontend/src/components/`. Keep the pure logic (the helpers, the formatters) in a separate file
  next to the component and unit test it — `shared/utils/task.ts` and its test are the reference.
- **Never import a generated binding file directly.** Use `frontend/src/api/aria2.ts`. It wraps the generated modules behind a
  typed surface and normalises the nullable arrays and maps the generator produces.
- The **Go pump** pushes the snapshots; the frontend never polls the engine. The `tasks:snapshot` event carries the whole state,
  and `internal/pump` publishes it. Do not add a poll to "fix" a stale list: the pump is the reader, and it ticks.
- The stylesheet expresses every size in `rem`, because the zoom factor scales the root font size (`frontend/src/composables/useWindowScale.ts`).
- `color-scheme: dark` is set on `:root`. Without it, WebKitGTK renders the native select popup with a light background while
  the option text stays light, which makes the selected item appear blank.

## The Webview Gotchas

- **`navigator.clipboard` needs a secure context and a user gesture**, which a webview does not always provide. The copy
  buttons fall back to a hidden textarea plus `document.execCommand('copy')`.
- **A click that ends a text drag fires the row's click handler.** The console rows check `hasTextSelection()` first.
- **`user-select: none` on a copy button** keeps the button's label out of the text the reader selects.
- The clipboard fallback must not use `display: none`; it is positioned off-screen with `opacity: 0`.

## The Data

Everything lives in `pb_data/` next to the executable: `data.db`, `storage/`, `.bitmaher_key` (mode `0600`),
`aria2/session.txt` (the engine's session, which is what survives a restart) and `aria2/aria2-next.log`.
`BITMAHER_DATA_DIR` relocates it — use that to run against an isolated database during development and testing.

## Verification Policy

- Run the narrowest relevant checks while iterating.
- Before finishing, run the checks that match the changed surface from "Change Routing".
- A change to the engine layer is not done until `go run ./tools/e2e-check` passes against a real binary.
- If a required check cannot run locally, report the reason and the exact command that remains.

## Known Rough Edges

1. **The server mode has no authentication.** The download collections are readable by anyone who can reach the port. The
   desktop app is in-process and unaffected; the container image binds `0.0.0.0` and is affected.
2. **`go build ./...` fails on `build/ios`** with `function main is undeclared in the main package`. It is a separate `main`
   package behind the `//go:build ios` tag. Build the root package and `./internal/...` instead.
3. **npm 9.2.0 cannot resolve the vitest 4 peer tree.** Use `npm install --legacy-peer-deps`, or a newer npm.
4. **The bundled binaries are not in Git.** A fresh clone has none, so the application falls back to a system-installed
   `aria2-next`. Run `wails3 task common:fetch:aria2` for the bundled path.
5. **Cross-compiling to macOS needs CGO and a macOS toolchain**, because of Wails. The Windows cross-compile works.
